# netlib v0.17.6 — PF lock survives another program's `pfctl -d`, no pass rules, no unattended reload over a foreign anchor

2026-11-18. Three decisions taken after the real Mullvad VM test
(`docs/testing/reports/vm-test-report-2026-11-12.md`, VM test T28): D5 (finding N1),
D6 (the rest of audit finding F9) and D7 (audit finding F10, unattended runs).

## Why

- **N1.** Mullvad enables PF with `pfctl -e` (no reference) and runs `pfctl -d` when it
  disconnects. That turns PF off and clears our `pfctl -E` reference, so the lock went
  inert until the next boot or the next enable.
- **F9.** The anchor `com.apple/foxhole.dnsleak` is evaluated before Mullvad's kill
  switch, which loads after `com.apple/*`. Any `quick` pass rule in the anchor ends the
  evaluation there. v0.17.5 removed the Quad9 passes; the loopback, `utun0`–`utun15`
  and ICMPv6 passes were still there.
- **F10.** Migrating a pre-0.17.3 install reloads the main ruleset, which drops a VPN
  kill switch's anchor. It asks first, but an unattended run (`FOXHOLE_ASSUME_YES=1`)
  answers "yes" to everything.

## Change

### D5: the boot daemon re-runs every 60 s

- The LaunchDaemon plist has `<key>StartInterval</key><integer>60</integer>` next to
  `RunAtLoad`.
- The helper's `boot` action has a fast path in front of the retry loop: if the rules
  are loaded and our reference is held, it exits 0 silently (no log line, no reload).
  Idle runs therefore do not grow `/var/log/foxhole-pf.log`. `main_has_anchor` is not
  part of the check on purpose, so a custom `pf.conf` without `com.apple/*` does not
  make every run spin through the retries.
- When another program turned PF off, the next run reloads the anchor and takes a new
  reference (log line `boot: rules loaded into …` as before). The lock is back within
  60 s.
- `disable_pf_dns_lock` still boots the daemon out before flushing, so the periodic run
  cannot race a disable.

### D6: the anchor has no pass rules

- Removed `pass quick on lo0 all`, `pass out/in quick on { utun0 … utun15 } all` and
  `pass quick inet6 proto icmp6 all`. The anchor holds the optional `plain`-mode table
  and the four `block out quick on { IFACES } …` rules only (the rule text format is
  unchanged: the helper's interface re-render depends on it).
- The blocks are scoped to physical `en*` interfaces, so tunnels, loopback and ICMPv6
  are never matched and need no pass.
- `verify_dns_stack` check [2] now checks that the anchor's block rules are loaded
  (`port = 53`) instead of looking for the utun pass rules.
- Comments and `README.md` describe the new design.

### D7: no reload over a foreign anchor when unattended

- New `_pf_foreign_anchors` lists the anchors in the main ruleset other than
  `com.apple/*` and the legacy `com.hardening.dnsleak` (names are sanitised: characters
  outside `A-Za-z0-9._/*-` are shown as `?`).
- New `_pf_confirm_main_reload` (used by `_pf_legacy_cleanup`): with
  `FOXHOLE_ASSUME_YES=1` and at least one foreign anchor it warns, names the anchors and
  returns "skip" without calling `ask`; the existing "Reload skipped…" message follows.
  Interactive runs keep the warning and the question.

## Existing installs

The boot daemon loads the rules file and the plist as written at the time of the last
enable. Disable and enable the lock once to get the new rules (no pass rules) and the new
plist (`StartInterval`). Until then the old behaviour stays.

A manual `sudo pfctl -d` no longer turns the lock off for good: the daemon brings it back
within a minute. To get out of the lock (captive portal, troubleshooting), disable it
(`vpn_daily.sh` [2], netlib menu, or `reset_net_hardening`), which boots the daemon out first.

`CLAUDE.md` still lists the `utun0`–`utun15` pass rules as a design rule. That rule is
obsolete with this release; the maintainer needs to update it (it was not edited here).

## Tests

- `tests/ci/offline.sh`: the anchor has no `pass` rule in any mode and still has exactly
  four `block out quick on {` rules; the plist has `StartInterval` 60 and `RunAtLoad`;
  the helper's `boot` case tests `rules_loaded`/`held_token` before its retry loop and
  that fast path neither logs nor calls `do_start`; `_pf_foreign_anchors` and
  `_pf_confirm_main_reload` with a stubbed `pfctl` and `ask` (unattended + foreign anchor
  = skip without asking, stock ruleset = reload, interactive paths unchanged).
- `tests/vm/vmtest.sh`: T2, T12, T17, T26 follow the new anchor (no pass rules; T12 checks
  that DNS through a `utun` route does not hit the block rules, with a control query
  that does). T4 and T23 flush the anchor before the daemon re-run, because the re-run is
  a no-op while the lock is up. New T29 (lock returns after `pfctl -d`, idle runs are
  silent, nothing returns after disable) and T30 (unattended legacy migration keeps a
  foreign anchor). T28 (real Mullvad) polls up to 90 s for the lock after Mullvad
  disconnects and has an unattended F10 case.
- The VM suite has not been run for this release yet.
