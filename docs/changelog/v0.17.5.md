# netlib v0.17.5 — PF DNS lock: no Quad9 pass rules (audit F9)

2026-11-12. Fixes the part of audit finding F9 that a real Mullvad kill switch proved
(`docs/testing/reports/vm-test-report-2026-11-12.md`, VM test T28).

## Why

Mullvad loads its firewall as `anchor "mullvad"` **after** `anchor "com.apple/*"` in the
main ruleset. The lock's anchor `com.apple/foxhole.dnsleak` is evaluated first, and a
`quick` pass there ends evaluation before the kill switch. With the tunnel down and
lockdown mode on, the VM measured:

- `doh`: `pass out quick proto tcp to <Quad9> port 443` let HTTPS to Quad9 out.
- `plain`: `pass out quick proto { udp tcp } to <Quad9>` let plain DNS (53) and HTTPS
  to Quad9 out, outside the tunnel.
- `vpn`: no Quad9 rule, nothing left.

## Change

`prepare_pf_dns_lock_anchor` writes no pass rule for Quad9 in any mode. Exceptions are
expressed by not blocking, so the traffic falls through to the rest of the ruleset
(a kill switch included):

- `doh`: no Quad9 rule at all. The blocks only match ports 53 and 853, so DoH on 443 was
  never blocked by the lock; the pass rules only bypassed later rules.
- `plain`: `table <foxhole_quad9> const { 9.9.9.9 149.112.112.112 9.9.9.11 149.112.112.11 }`
  and the IPv4/any-family blocks become
  `block out quick on { IFACES } proto { udp tcp } to ! <foxhole_quad9> port 53|853`.
  The IPv6 blocks are unchanged (they never had a Quad9 exception).
- `vpn`: unchanged.

Without a kill switch the behaviour is the same as before: Quad9 443 open in `doh`,
plain DNS to Quad9 open in `plain`, everything else on 53/853 blocked on `en*`.

The boot helper's interface re-render only rewrites the `block out quick on { … }`
prefix, so it handles the new destination as is. Disable flushes the anchor with
`-F all`, which also removes the table.

**Existing installs:** the boot daemon loads the rules file as written. Disable and
enable the lock once (or pick the mode again) to get the new rules.

## Not changed (still open from F9)

The other unscoped quick passes stay: `pass quick on lo0`, `pass out/in quick on
{ utun0 … utun15 }` and `pass quick inet6 proto icmp6 all`. They are not needed by the
blocks (which only match `en*`), but CLAUDE.md lists the utun passes as a design rule
and `verify_dns_stack` check [2] looks for them. Under a kill switch they let ICMPv6 and
traffic on another utun past it. Not measured yet (no IPv6 on the test network); needs a
decision.

## Tests

- `tests/ci/offline.sh`: doh has no Quad9 rule; plain has the table and two
  `! <foxhole_quad9>` blocks; no mode has a pass rule that names an address.
- `tests/vm/vmtest.sh`: T3, T17 (table contents, flushed on disable), T23 (mode
  detection by the table name) follow the new rule text. T28 (real Mullvad) is the
  regression test for F9.
