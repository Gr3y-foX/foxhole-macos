# netlib v0.17.4 — PF lock enable/disable recovery (audit F2, F3)

Branch `private-all`, 2026-11-10. Findings from `docs/dev/AUDIT_PF_LOCKOUT_REPORT.md`.

## What changed

- **F2 (`disable_pf_dns_lock`):** the anchor is flushed right after the boot daemon is
  removed, before the helper re-install. A failing `mktemp` or `install` in the re-install
  no longer leaves the block rules loaded.
- **F3 (`enable_pf_dns_lock`):** the helper's `start` and `status` run synchronously
  before the boot daemon is installed. The status poll loop is gone. On failure the lock
  is stopped and no plist is left behind, so the lock cannot turn on at the next boot
  while the session reports it failed. If the daemon install fails after a good start,
  the lock is rolled back.
- `tests/ci/offline.sh`: three static checks for the new order.

## Not changed (still open in the audit)

F1 (`restore.sh` does not tear down the lock), F4–F17. F13 (the menus do not guard
`enable_pf_dns_lock`, so `set -e` ends the menu on failure) is still open.

## Verification

Offline checks, `bash -n` and `shellcheck -S warning` only. The VM suite (T20–T26
proposed in the report) is **not** run yet: needs the `Disc Samsung T7` SSD mounted and
the reboot phases.
