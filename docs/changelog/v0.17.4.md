# netlib v0.17.4 — PF lock enable/disable recovery (audit F2, F3)

Branch `private-all`, 2026-11-10. Findings from `docs/dev/AUDIT_PF_LOCKOUT_REPORT.md`.

## What changed

- **F2 (`disable_pf_dns_lock`):** the anchor is flushed right after the boot daemon is
  removed, before the helper re-install. A failing `mktemp` or `install` in the re-install
  no longer leaves the block rules loaded.
- **F3 (`enable_pf_dns_lock`):** the helper's `start` and `status` run synchronously
  before the boot daemon is installed. The status poll loop is gone. On failure the lock
  is stopped and no plist is left behind, so the lock cannot turn on at the next boot
  while the session reports it failed. If the daemon install fails after a good start,
  the lock is rolled back.
- **F1 (`restore.sh`):** the backup's restore script now removes the PF DNS lock on every
  run: boots out the LaunchDaemon, removes its plist, flushes the foxhole anchor, releases
  only our PF reference (the token file), and deletes the helper and rules file. It no
  longer leaves the lock in place when the snapshot was taken with it on. The snapshot's
  lock state is deliberately not restored. A restored lock would bring back the block the
  user is trying to get out of; re-enable it from the menu if you want it back.
- **F10 (legacy `pf.conf` migration):** the main-ruleset reload now asks first and says
  what it replaces. Declining skips it. The `restore.sh` header already warns to reload
  only with no VPN kill switch active.
- **F11 (helper `start`):** every failure after the rules are loaded flushes the anchor
  before exiting, so block rules never stay without a held reference.
- **F12 (helper `start`):** if the token file cannot be written, the reference is released
  and the anchor flushed.
- **F13 (menus):** `enable_pf_dns_lock` failure is reported and the menu stays open, in
  `mac-hardening-netlib.sh` and `vpn_daily.sh`.
- **F15 (`prepare_pf_dns_lock_anchor`):** the temp file is removed when the install fails.
- **F16 (`reset_net_hardening`):** each of the three disables runs in a subshell, so a
  failure in one no longer skips the others.
- `tests/ci/offline.sh`: static checks for the enable/disable order, the restore teardown
  and each fix above.

## Not changed (still open in the audit)

F4 is covered by the F3 synchronous start, but not yet verified in the VM. F5 (new mode
is written before the confirmation), F6 (captive networks: wording only), F7 (interface
list is replaced, not merged: product decision D2), F8 (no `KeepAlive` retry, no
`com.apple/*` check in `status`), F9 (`quick` pass rules can pre-empt a kill switch: needs
a real kill switch to confirm), F14 (root-run content staged in user-owned temp files) and
F17 (`vpn_daily.sh` never snapshots).
